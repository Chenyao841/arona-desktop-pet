# 陪玩点评模式（Commentary）方案

> 文档状态：**方案已确认 · P1 最小闭环已实现（2026-09-13）** · 编写日期：2026-09-12
> 目标：新增一个"陪玩"状态 —— 短间隔读屏截图，每次给一句弹幕风短点评，像在陪你玩；允许人工告知当前在做什么，没告知就自己判断；该状态下**不做鼠标跟踪，点评时也不看回用户**。

---

## 0. 结论速览

| 问题 | 结论 |
|---|---|
| 能在现有闲置上改吗？ | **不能直接复用**，要新增独立状态与计时器（现有闲置被"用户一动就清零"和"最小 120s 门槛"卡死，见 §1） |
| 需要状态机吗？ | **需要**，但很轻：一个模式开关 + 一个"语境"维度（B站/麻将/蔚蓝档案/办公/其它），见 §3 |
| 点评怎么生成最划算？ | **一步法**：把"点评要求"直接写进视觉调用的提示词，让视觉模型一次输出点评 JSON（复用现有 `showResult` 播放链路），延迟 ≈ 一次视觉调用，成本最低，见 §4.1 |
| 会不会很烧钱/很吵？ | 靠三件事控制：**画面变化检测**（没变不点评）+ **连续上限与静默期** + **短句**（≤20 字）；估算见 §7 |
| 鼠标跟踪怎么处理？ | 本模式下 `gazeOnUser()` / `scheduleIdleFollow()` 全部置空，点评时保持"看屏幕"的姿态，见 §6 |
| 会被什么打断？ | 用户说话、TTS 播放中、麻将自动打牌、抽卡、牛奶/调整模式 —— 一律让路，见 §5.3 |

## 0.1 已确认的决策（用户 2026-09-13 拍板）

| # | 决策 | 结论 |
|---|---|---|
| 1 | 生成方式 | **一步法**（视觉模型直接出点评 JSON） |
| 2 | 语境判定 | 进入指令可带语境（`陪我玩 看B站`）；不带则**自动判定兜底** |
| 3 | 是否出声 | **出声**，但用三招降低"烦人"感：**调小本状态音量** + **概率延长响应间隔** + **绝不长篇**（≤20 字硬截断） |
| 4 | 进入方式 | **指令 + 状态按钮**（🎬，与 🥛 同列） |
| 5 | 截图留存 | **留 60 分钟**（便于测功能），到点自动清理 |
| 6 | 麻将/抽卡 | **完全暂停点评** |

## 0.3 修复记录：点评里混入「思考过程」（2026-09-13）

**现象**：点评里出现「用户想让我以阿罗娜的语气点评…」这类句子，且因为按 `max_chars` 硬截断，拿到的是思考过程的一小段。

**根因**：视觉模型 `deepseek-v4-flash-vision-exp` 是**推理型**，会先吐思考过程；点评初始只给了 `max_tokens=300`，被思考吃光后 `content` 为空，而原 `chatVision()` 里有一条"content 为空则回退 `reasoning_content`"的兜底（那是给「桌面视觉描述」用的）→ **思考文本被当成点评**，再被长度上限截断。

**修法（四处）**：
| # | 改动 |
|---|---|
| 1 | 新增 `DeepSeekService.chatVisionContentOnly()`：**content 为空就返回 null，绝不回退 reasoning**（点评专用，原 `chatVision` 行为不变，桌面视觉不受影响） |
| 2 | `CommentaryService.parseReply()` 改为**严格模式**：找不到 JSON 对象一律返回 null（丢弃本次）—— 早先"整段当点评"的兜底正是把思考文本放进来的元凶 |
| 3 | 新增 `cleanupComment()`：去引号/前缀，并识别思考特征句式（"用户想让我""我需要先""让我想想""根据要求"…）→ 直接判为非点评丢弃 |
| 4 | 长度策略改为：**超过 `max_chars × 3` 直接丢弃**（疑似思考过程），仅轻微超长才按标点截断；同时 `max_tokens` 提为**可配置**（新增 `commentary_config.max_tokens`，默认 1200，设置页可改），并显式要求"第一个字符必须是 `{`、不要任何思考过程" |

丢弃时会在日志/设置页「试点评」结果里给出原因（如"模型没有按要求返回 JSON"、"点评过长疑似混入思考过程"）与原始返回片段，便于继续调 prompt。

## 1. 现状与冲突点（必须先解决）

### 1.1 现有闲置机制（`桌宠桌面版.html` `initIdle()`）

```
每秒 tick：
  idleSeconds++
  ├─ 数据库固定触发：user_operation = idle1/idle2/…  到点播固定内容（idleTriggers）
  └─ AI 智能闲置：满足 [2 分钟无 AI 调用] 且 [idleSeconds ≥ aiIdleInterval(默认180s)]
       ├─ 若开了桌面视觉 → 30% 概率截屏 + 视觉理解 + 评论（现在只有这一条路会看屏幕）
       └─ 否则从 idle_activities 抽活动（延续性/单发/睡觉），AI 返回 sleep 可把间隔调到最大 1800s
  触发后：scheduleIdleFollow(...) → 视线跟随鼠标 20s
监听 mousemove/keydown/click/scroll → idleSeconds = 0   ← 关键冲突
```

### 1.2 三个冲突点

| # | 冲突 | 影响 | 处理方向 |
|---|---|---|---|
| 1 | **用户一动就清零** | 你正在打麻将/看B站（一直在动鼠标）时，pet **永远不会**进入闲置 → 陪玩点评根本触发不了 | 新模式**不订阅**这些重置事件，改为"只被对话/TTS/自动化打断" |
| 2 | **最小间隔 120s + 2 分钟无 AI 门槛** | 想 8~20 秒点评做不到 | 新模式用**独立计时器**与自己的间隔参数，与现有闲置解耦 |
| 3 | **触发后自动跟随鼠标 20s** | 与"不做鼠标跟踪、不看回用户"直接冲突 | 新模式不调用 `scheduleIdleFollow()` / `gazeOnUser()`，并可临时把 `holdGaze` 置空 |

> 现有闲置**保持不动**（它负责"你不在时自言自语"），新模式是**并列的第二套闲置行为**，两者互斥：陪玩模式下暂停普通 AI 闲置。

## 2. 体验目标（用一句话描述）

> 你在打麻将/看B站/抽卡，旁边坐着阿罗娜，她每隔十几秒瞄一眼你的屏幕，冒一句短促的吐槽或惊呼（"诶诶诶这什么展开！"），说完继续安静看着屏幕；你不理她她也不会缠你；你一说"陪我玩"她就进入这个状态，说"别看了"就退出。

要点：**短、频、像弹幕、不打扰、不看你**。

## 3. 状态机设计

### 3.1 状态定义

```
CommentaryMode（陪玩点评）
├── mode：off | on                       ← 总开关（指令 / 设置页开关）
├── context：bilibili | mahjong | bluearchive | work | other   ← 当前语境
│     ├── source：manual（人工告知）| auto（视觉判定）| default
│     └── manualTtl：人工告知的保持时长（默认 15 分钟，到期回落到 auto）
├── 运行参数：intervalSec / maxStreak / silenceSec / minChangeScore / voiceOn
└── 运行时状态：lastShotAt / lastCommentAt / streak / silenceUntil / lastImageHash
```

### 3.2 状态迁移

| 事件 | 迁移 |
|---|---|
| 指令 `陪我玩` / `专心看你玩` / `陪玩模式`（可在指令库改别名） | mode: off → on，context: auto |
| 指令 `现在在打麻将` / `我在看B站` / `这是蔚蓝档案` / `随便看看` | context: 人工锁定（manual，TTL 15 分钟）；`随便看看` → other 且关闭自动判定 |
| 自动识别（视觉调用顺带判定，见 §4.1） | 若当前是 auto 且判定置信度高 → 更新 context |
| 指令 `别看了` / `安静点` / `陪玩结束` | mode: on → off（恢复普通闲置与鼠标跟随） |
| 用户开始对话 / TTS 播放 / 麻将自动打牌 / 抽卡 / 牛奶 / 调整模式 | 挂起点评（不退出模式），结束后恢复 |
| 连续点评达 `maxStreak` | 进入 `silenceSec` 静默期，之后 streak 归零 |
| 静置超过 `idleExitMin`（可选，默认关） | 自动退出模式 |

### 3.3 语境的默认配置（每个语境一套风格 + 参数）

| context | 识别线索（给视觉模型） | 点评风格要求 | 特殊限制 |
|---|---|---|---|
| `bilibili` | B站播放页/直播页/视频播放器 | 追番式吐槽、惊呼、接梗，可用"诶诶诶""这什么展开" | 不剧透、不刷弹幕梗 |
| `mahjong` | 麻将牌桌、手牌、立直/和了界面 | 只点评**氛围**（"这手牌有点难办呀""差一点！"） | **严禁给操作建议**（避免干扰自己的读牌/自动打牌流程） |
| `bluearchive` | 蔚蓝档案界面（抽卡/战斗/剧情/主界面） | 认出场景并短促反应（"出金了！""老师这关好难"） | 不剧透剧情；抽卡自动化进行中不点评 |
| `work` | 代码编辑器/文档/浏览器工作页 | 关心式（"老师又在写代码…记得喝水"） | 不念屏幕上的文字、不做技术评价 |
| `other` | 兜底 | 泛用陪看（"哇，老师在看这个呀"） | 不编造画面里没有的东西 |

**通用硬约束（写进提示词）**：≤20 字、一句话、不重复上一次内容、不念屏幕文字、不说"我看到"这类废话、不指挥你操作、不要每句都换表情。

## 4. 每次点评的流水线

```
① 挂起检查（用户说话中/TTS 播放/麻将或抽卡自动化/牛奶模式 → 跳过本次）
② 截屏（Robot 全屏 → 降采样到宽 800px → JPEG base64；约 100~200ms CPU）
③ 画面变化检测（本地，不调 AI）
     ├─ 缩到 64×40 灰度 → 与上一张逐像素平均差；低于阈值 → 跳过（省一次视觉调用）
     └─ 差异"剧变"（切窗口/切场景）→ 标记优先点评（更像个真人会接梗）
④ 一次性视觉调用（把语气、语境、长度、去重要求全写进 prompt）
     └─ 让它返回 JSON：{"context":"mahjong","boat_text":"…","motion":"aluona_xxx.png"}
⑤ 解析 → 走现有 showResult() 播放链路（文字 + 表情 + 短句 TTS + 气泡）
⑥ 记账：lastCommentAt / streak++ / 存 event_book（供后续对话引用）
```

### 4.1 为什么用"一步法"（视觉模型直接出点评）

| 方案 | 调用次数 | 延迟 | 成本 | 备注 |
|---|---|---|---|---|
| 两步（现有桌面视觉）：视觉出"描述" → 文本模型改编成阿罗娜口吻 | 2 | 4~8s | ×2 | 描述里容易丢掉画面细节，改编还可能跑偏 |
| **一步（推荐）**：视觉模型直接按人设输出点评 JSON | **1** | **2~4s** | ×1 | 复用现有 `chatVision` 通道，只需换 prompt 与 `max_tokens` |

一步法落点：
- 后端 `DeepSeekService` 已有 `chatVision(base64, prompt)`（模型 `deepseek-v4-flash-vision-exp`，走配置里的 `api_url`）
- 新增一个入口：`user_operation = "commentary"`（或独立接口 `/ai/commentary/once`），内部：截屏 → 变化检测 → 组装 prompt → `chatVision` → 解析 JSON → 返回 `Result`（与 `/talk` 同结构）
- prompt 里带上：角色人设（取 `ai_prompt` 的 system 精简版）+ 当前语境 + 上一句点评（去重用）+ 长度/风格硬约束
- `max_tokens` 从现有 4096 降到 **300**（短点评足够，响应更快）

### 4.2 画面变化检测（省成本的关键）

- 在 Java 端做：把截图再缩成 64×40 灰度，算与上一张的平均绝对差（0~255 尺度）
- 阈值分三档：`< 3` 视为静止（跳过）、`3~15` 一般变化（正常点评）、`> 15` 剧变（优先点评）
- 每次点评后把当前帧存为基准帧；陪玩模式退出时清空
- 效果预估：静止画面（看文档/挂机）几乎不点评；游戏/视频场景变化大 → 点评自然

## 5. 触发节奏与"话痨"控制

### 5.1 参数（建议默认）

| 参数 | 默认 | 说明 |
|---|---|---|
| `intervalSec` | **12** | 两次点评的最小间隔（5~60 可调） |
| `minChangeScore` | 3 | 画面变化阈值，低于则跳过 |
| `maxStreak` | **3** | 连续点评上限，达到后进静默 |
| `silenceSec` | **45** | 静默时长 |
| `afterTalkSilenceSec` | 20 | 刚跟你聊完之后的静默 |
| `voiceOn` | 开 | 是否出声（关掉只显示文字，省钱省时） |
| `maxCommentChars` | 20 | 点评长度硬上限 |
| `keepScreenshots` | 关 | 是否把点评截图存 `desktop_vision_log/` |

### 5.2 有效频率估算（默认参数）

- 理论上限：60/12 = 5 次/分钟
- 叠加上"画面无变化跳过"（估掉 40%）与"静默期"（估掉 20%）→ 实际 **约 2~3 次/分钟**
- 一局麻将（30 分钟）≈ 40~60 条点评；一次抽卡（2 分钟）≈ 4~6 条

### 5.3 挂起（让路）优先级

| 场景 | 处理 |
|---|---|
| 用户正在打字/刚发过消息 | 静默 `afterTalkSilenceSec` |
| TTS 正在播报 | 跳过，等播完 |
| 麻将自动打牌 / 抽卡自动化进行中 | **完全暂停**（既避免声音干扰，也避免和"读牌/点击"抢 CPU 与截图） |
| 🥛 牛奶模式 / 🎯 调整模式 / ⚙ 选项编辑 | 跳过 |
| 直播模式 + 有弹幕在刷 | 弹幕优先；点评可降频 |
| AI 正在生成长回复 | 跳过（避免两条回复打架） |

## 6. 鼠标跟踪与"不看回用户"

你要的两点很明确，做法是**在播放链路上挂钩子**：

| 现有调用 | 位置 | 陪玩模式下的行为 |
|---|---|---|
| `gazeOnUser(ms)`（出响应/说话时回到看用户） | `playSpeech()` / `playAudio()` | **置空**（本模式下不调用） |
| `scheduleIdleFollow(...)`（闲置说完跟随鼠标 20s） | `initIdle()` / 各 showResult 后 | **不调用** |
| `l2dBridge.holdGaze()` | 由 `gazeOnUser` 触发 | 不触发 → 空闲逛视可继续（或固定眼神） |
| 可选：点评时的姿态 | — | 用现成的**眼神动作**机制让眼球轻微上瞟（"在看屏幕"），播完自动回中 |

实现建议：给桌面页加一个 `commentaryMode` 标志，并让 `gazeOnUser()` 内部首行判断 `if (commentaryMode) return;` —— 一处改动即可覆盖所有调用点，退出模式后自动恢复。

## 7. 成本 / 性能估算

| 项 | 每次 | 说明 |
|---|---|---|
| 截屏 + 缩放 + JPEG 编码 | ~100~200ms CPU | 与麻将/抽卡同时跑会互抢，所以自动化期间暂停 |
| 视觉调用 | 800px JPEG（base64 约 100~200KB）+ prompt，`max_tokens 300` | 比纯文本贵，但一次只出一句话 |
| TTS 合成（短句） | **1~3 秒**（实测；与长短关系不大，受 GPU 状态影响） | 点评短 → 不会拖长；命中缓存则 0.05~0.28s（动态内容基本不会命中） |
| 一条点评总延迟 | **约 3~5 秒**（截图+视觉 2~4s，语音并行） | 文字在视觉返回后立即显示（复用"首句立即显示"），所以"体感"是 2~4 秒 |
| 每小时调用量（默认参数） | 视觉 ~120~180 次 | 想再省：调大间隔 / 提高变化阈值 / 关语音 |

> 对比：现有"AI 智能闲置"每 3 分钟一次、每次 1 次文本调用 → 新模式是**视觉调用密度提高约 5~8 倍**，这是主要成本增量。

## 8. 配置与界面

### 8.1 建议新表（不动现有表）

```sql
CREATE TABLE commentary_config (
  id                INT PRIMARY KEY AUTO_INCREMENT,
  enabled           TINYINT DEFAULT 0,        -- 模式开关（也可只由指令控制，不入库）
  interval_sec      INT DEFAULT 12,
  min_change_score  INT DEFAULT 3,
  max_streak        INT DEFAULT 3,
  silence_sec       INT DEFAULT 45,
  after_talk_sec    INT DEFAULT 20,
  voice_on          TINYINT DEFAULT 1,
  max_chars         INT DEFAULT 20,
  keep_screenshots  TINYINT DEFAULT 0,
  auto_detect       TINYINT DEFAULT 1,        -- 是否允许视觉自动判定语境
  manual_ttl_min    INT DEFAULT 15,
  updated_at        TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP
);

-- 每个语境一行（风格提示词可编辑）
CREATE TABLE commentary_context (
  id       INT PRIMARY KEY AUTO_INCREMENT,
  code     VARCHAR(20) UNIQUE,   -- bilibili / mahjong / bluearchive / work / other
  label    VARCHAR(40),          -- 中文名（设置页显示）
  enabled  TINYINT DEFAULT 1,
  prompt   TEXT                  -- 该语境的风格要求（拼进视觉提示词）
);
```

### 8.2 设置页

新增侧边页 **🎬 陪玩点评**（与其它模块同规范：首行模块开关）：
- 开关 + 参数（间隔 / 变化阈值 / 连续上限 / 静默 / 语音开关 / 截图留存）
- 语境表格（每行：中文名 / 开关 / 风格提示词，可直接编辑）
- 当前状态显示：模式 on/off、当前语境（含 source: 人工/自动）、上一次点评时间与内容、累计条数
- 手动切换语境的按钮（等同指令）
- 一条"试点评一次"按钮（立刻截屏点评一次，便于调 prompt）

### 8.3 指令（并入指令库，可在设置页改别名）

| 主指令 | 作用 |
|---|---|
| `陪我玩` | 进入陪玩点评模式 |
| `别看了` | 退出模式 |
| `现在在打麻将` / `我在看B站` / `这是蔚蓝档案` / `随便看看` | 人工告知语境（拿不准就用 `随便看看` 交给自动判定） |
| `点评一下` | 立即点评一次（不等计时器） |

### 8.4 事件簿

每次点评写一条 `event_book`（如 `[commentary] 老师打麻将时阿罗娜吐槽："这手牌有点难办呀"`），这样之后正常对话时它还能引用"刚才我在旁边看你打牌"。

## 9. 分期实施

| 阶段 | 内容 | 验收 |
|---|---|---|
| **P1 最小闭环** | 指令进入/退出 + 固定 12s + 一步法点评 + 本模式下不跟随鼠标/不看回用户 | 说"陪我玩"后，屏幕内容变化时每十几秒能听到一句短点评；说"别看了"停止 |
| **P2 语境状态机** | 人工告知语境 + 自动判定（同一视觉调用顺带返回）+ 每语境风格提示词 | 说"现在在打麻将"后点评不再提B站内容；不告知时能自己认出在做什么 |
| **P3 省钱与不烦人** | 画面变化检测 + 连续上限/静默期 + 去重（带上一条点评）+ max_tokens 收敛 | 静止文档页几乎不点评；不会连续轰炸 |
| **P4 联动与打磨** | 与直播/麻将/抽卡挂起联动、事件簿记录、试点评按钮、可选自动进入 | 自动打牌时完全安静；点评入事件簿可在对话中被引用 |

## 10. 风险与注意

1. **视觉模型边界**：截图必须 800px 宽（代码实测 1000px 会返回空）；`max_tokens` 别给太大（现有 4096 是给"描述型"用的），点评用 300 即可
2. **成本**：视觉调用密度是全项目最高的一项，务必靠"变化检测 + 静默期 + 可关语音"兜住；建议先在小范围（只看B站）试跑一小时看账单
3. **干扰**：打麻将/抽卡时**必须自动暂停**（声音与截图都会干扰流程，还有 CPU 争抢）
4. **隐私**：默认**不保存**截图；若开启留存，应在设置页标明目录并提示定期清理
5. **剧透与冒犯**：提示词里要限制"不剧透剧情 / 不评价你的操作水平 / 不念屏幕上的私密文字（聊天框、文件内容）"——尤其是办公语境
6. **与直播模式并存**：弹幕优先，点评让路；两者都用视觉时注意不要同时触发
7. **重复感**：带上"上一次点评内容"让模型避免复述；同一画面连续触发时靠变化检测挡住
