# QQ 机器人 · P4 进度（回复节奏 + 防刷 + 私聊闲聊 + 引用回复）

> 更新：2026-10-20 · 承接 P0/P1/P3（P2 闲置响应按你的要求跳过）
> 本文覆盖这一轮 6 个需求；语音（GPT-SoVITS）确认**不做**，机器人只发文字 + 表情图。

## 一、这一轮改了什么

| 需求 | 实现 |
|---|---|
| 管理员私聊能闲聊（不只是指令） | 私聊非指令内容走 AI，独立会话 `qq_p{QQ号}` + 独立记忆 `阿罗娜-私聊{QQ号}` |
| 引用回复 | 回复第一段带 `{type:"reply"}` 引用原消息，群里能看清在答哪句 |
| 同人冷却可关闭 | `/cooldown 0` 或 `ZC_QQ_USER_COOLDOWN=0` |
| 多条消息按入栈顺序回复 | 每个群一条**单线程车道**，任务按到达顺序串行，前一条没发完后一条不插队 |
| 固定延迟 + 去抖 | 收到 @ 后等 `qq.reply-delay-sec`（默认 3s）再发；窗口内同人再 @ → 重置延迟、**只回一条** |
| 思考超过延迟就立刻回 | 到点时若模型还没想完，就等它想完立刻发（总耗时 = 思考耗时，不叠加） |
| 恶意 @ 防护 | 延迟窗口内同一人连发达到 `qq.blacklist-burst`（默认 4）→ 拉黑、本条不回；仅管理员能解 |
| 额度用尽固定回复 | 被 @ 时不调模型，回固定文案 `qq.quota-reply`（可改） |

## 二、一条消息的完整时间线

```
t=0.0s   收到 @ 小明「阿罗娜你在吗」
         └─ 立刻开始思考（调模型，不阻塞）
         └─ 发送时刻 = t+3s
t=0.4s   小明又 @「在吗在吗」
         └─ 思考不重跑（省钱），发送时刻重置为 t=3.4s，仍然只有一条回复
t=1.0s   老师 @ 了它（另一个人）
         └─ 同一群的车道里排在后面，必须等小明那条发完
t=3.4s   发小明那条（引用最新的「在吗在吗」）+ 一张表情
t=4.0s   才轮到老师那条（哪怕老师那条早就想好了）
```

例外：**管理指令不排队、不加延迟**（你要的"快捷调整"），`/delay` `/cooldown` 这类发出去立刻生效。

## 三、新增/变更的管理指令

| 指令 | 作用 |
|---|---|
| `/delay <秒>` | 固定回复延迟，`0` = 立刻回（范围 0~120） |
| `/cooldown <秒\|0>` | 同人冷却，`0`/`off` = 关闭（范围 0~3600） |
| `/quote on\|off` | 引用回复开关 |
| `/ban <QQ> [原因]` | 拉黑某个 QQ（全局生效，所有群都不再回它） |
| `/unban <QQ>` | 解除拉黑 |
| `/blacklist` | 看黑名单（谁、原因、时间） |

`/status` 也补了几项：回复延迟、同人冷却、引用开关、排队中回复条数、黑名单人数。

## 四、配置项（环境变量 → application.yml）

| 环境变量 | 默认 | 说明 |
|---|---|---|
| `ZC_QQ_REPLY_DELAY` | 3 | 固定回复延迟（秒），0 = 立刻回 |
| `ZC_QQ_BLACKLIST_BURST` | 4 | 延迟窗口内连发几次拉黑 |
| `ZC_QQ_QUOTE` | true | 引用回复 |
| `ZC_QQ_QUOTA_REPLY` | 今天我说话太多啦… | 额度用尽的固定说明 |
| `ZC_QQ_AI_THREADS` | 4 | 同时"思考"的消息数 |
| `ZC_QQ_USER_COOLDOWN` | 60 | 同人冷却（0 = 关闭） |

## 六、这轮修掉的 bug

**私聊回复发给了 QQ 0**：`QqReplyQueue.process()` 把 `groupId`（私聊时是 0）当目标传下去，
`send_private_msg` 就变成 `user_id=0`。已改成「私聊目标是 QQ 号、群聊目标是群号」，
并顺手让模型知道私聊对面就是管理员本人（之前它会问"你是哪位呀"）。

## 八、追加：表情包收紧（只在大情绪 + 限频时发）

原先「每条回复都跟一张表情」太吵，改成**三道闸门**：

| 闸门 | 规则 | 配置 / 指令 |
|---|---|---|
| ① 情绪够大 | 只有 `激动/害羞/生气/慌张/难过/开心/震惊/俏皮` 才配图；`认真/怀疑/困惑/无语/温柔/平静` 一律不发。<br>AI 没给 emotion 时看文本强信号：连续 ≥2 个感叹号、或「哈哈/嘿嘿/呜呜/哇/啊啊/讨厌/太好了…」 | `qq.emoji-strong-emotions` / `ZC_QQ_EMOJI_STRONG` |
| ② 间隔冷却 | 同一个群里，**中间至少隔 5 条纯文字回复**才允许再发一张；发出后计数清零。<br>（从没发过图的群不受限，开机第一句强情绪也能配图） | `qq.emoji-min-gap` / `ZC_QQ_EMOJI_GAP`；运行时 `/emoji gap 5` |
| ③ 随机抑制（可选） | 过了前两道的回复再随机保留一次 | `qq.emoji-probability`（默认 100） |

新增指令：`/emoji`（概况：开关、间隔、强情绪集合、已发数）、`/emoji gap <次数>`、`/emoji on|off`。
`/status` 里也会显示当前的表情包开关与间隔。

**验证（`ZC_QQ_EMOJI_GAP=1`，四种组合一次跑完）**：

```
①「今天是星期三吧？」（平淡，首次无间隔限制） → [QQ] 表情包跳过：这条情绪偏平（emotion=null）
②「阿罗娜你今天怎么这么可爱！！」（强情绪）   → [QQ] 表情包: 11.png（闭眼大笑）第 2 条回复  ← 发了 ✓
③「哇！！你也太厉害了吧！！」（强情绪但刚发过）→ [QQ] 表情包跳过：距上次发图只隔了 0 条回复（需要 1 条）
④「现在几点了？」（平淡，间隔已过）           → [QQ] 表情包跳过：这条情绪偏平（emotion=null）
/emoji      → 开启，素材 39 张，发放条件 ①②，本次已发 1 张
/emoji gap 5 → 表情包间隔已设为：中间至少隔 5 条回复
```

## 九、追加：两种「主动接话」

被 @ 才说话太呆，加了两条**不需要 @** 的主动反应。都是独立车道（不占用群的回复顺序），也不写进 AI 会话历史。

### 9.1 跟风复读机（纯代码，不花 token）

| 项 | 规则 | 配置 |
|---|---|---|
| 触发门槛 | 同一句话被 **3 个不同的人**重复（`parrot-min-users`） | `ZC_QQ_PARROT_MIN_USERS` |
| 概率 | 每次都掷 **33%**（`parrot-probability`），没中就等第 4、第 5 个人再掷 | `ZC_QQ_PARROT_PROB` |
| 只复读一次 | 同一句成功复读后不再复读；成功后静默 N 次触发机会（默认 1） | `ZC_QQ_PARROT_COOLDOWN` |
| 安全阀 | 每组每小时最多 3 次；超过 60 字不参与；180s 窗口内统计 | `ZC_QQ_PARROT_MAX_HOUR` 等 |
| 不 @ 人 | 复读就是原样发一句，不带 @、不带引用 | — |

**踩过的坑**：会把自己的回复当成人话参与统计 → 加 `QqBotReplyMemory`（每组最近 20 条自己发的内容，
10 分钟 TTL），判断"这句是不是我说过的"（双向包含，防止标点差异漏判）。

### 9.2 护短（会调 AI，管理员被调侃时站出来）

群友拿管理员开涮时，阿罗娜作为"管理员的小跟班"出面反驳。

| 项 | 规则 | 配置 |
|---|---|---|
| 触发 ① | 消息里 **@ 了管理员 QQ** + 含调侃性关键词 | `qq.admin-qq` + `qq.defend-keywords` |
| 触发 ② | 消息里出现**管理员的群名片/昵称** + 调侃语气（关键词，或 `就这/不会吧/啧啧/呵呵/笑死/离谱/绷不住/又来了吧/行不行啊/不靠谱`） | 群名片机器人自动登记（管理员在该群说一句话就记住，**优先群名片而不是 QQ 名**）；再配 `qq.defend-admin-alias` 补额外叫法 |
| 触发 ③ | **引申调侃词**（羊肉/烤羊/涮羊肉…）+ 管理员**刚在这个群发过言**（默认 180s 内） | `qq.defend-mock-words` + `qq.defend-context-sec` |
| 冷却 | 护短一次后**跳过 3 次触发机会**（`defend-cooldown-triggers`） | `ZC_QQ_DEFEND_COOLDOWN` |
| 安全阀 | 每组每小时最多 5 次（要调模型，防烧钱） | `ZC_QQ_DEFEND_MAX_HOUR` |
| 不护的情况 | 管理员自嘲、没指名道姓、叫了名字但没调侃、引申词但管理员没在说话、`/` 开头的指令、纯图片/表情/语音、群被关闭或静音 | — |
| 回复形式 | 一两句、引用调侃那条、走固定延迟；`userOperation=qq_chat_defend` 有专属提示词 | — |

「在说管理员」的三种叫法，按优先级：

1. **@ 管理员** —— 最明确
2. **叫名字** —— 群名片优先（`sender.card`），没填才退回 QQ 昵称。所以「小羊羔」这种群昵称
   只要管理员在那个群说过一句话就会被记住，**不用额外配**；`qq.defend-admin-alias` 是给
   「还没见他发过言的群」以及「羊羊/羊羔子」这类变体用的，默认 `小羊羔,小羊`
3. **只提引申词不点名** —— 「今晚想吃烤羊」。这种必须靠上下文：管理员最近
   `qq.defend-context-sec`（默认 180s）内在这个群发过言，才算在说他；否则纯当聊吃的，不管

注意：引申词这条路**不需要**再命中调侃词（「烤羊」本身就是指着他开玩笑），
但如果同时命中了调侃词（「羊肉串真香，不过某人又鸽了」），不用上下文也直接护。

提示词要点：护犊子但不真生气、可夸张可幽默、不人身攻击、不长篇大论、不透露管理员隐私、不追着人不放。

新增指令：`/defend`（概况：开关、叫法、引申词、冷却、本群这一小时护短次数、本群自动记住的群名片、管理员上次发言多久前）、
`/defend on|off`、`/defend alias 小羊羔,小羊`（运行时改叫法，`reset` 恢复配置）、`/defend keywords`、`/defend mock`。
`/status` 里也加了「主动接话：复读机 开（概率 33%），护短 开（冷却 3 次触发，上限 5 次/时）」。

**验证（离线，不起 Spring / 不连 NapCat / 不调真模型）**：

```
护短功能校验：通过 34 项，失败 0 项      ← 触发判定 / 不该触发的五种 / 冷却 3 次 / 每小时上限 5 次
                                         /defend 开关 / 叫法配置 / 引申词+上下文 / /defend alias 运行时改
Router 护短接线校验：通过 20 项，失败 0 项  ← @管理员的 QQ 有没有真传下去、群名片「小羊羔」有没有被记住、
                                           「想吃烤羊」有没有走到上下文判定、@机器人自己不串到护短
```

> 接线时踩的坑：`atAdminQqs` 的声明被脚本批量替换写成了两份（私聊 + 群聊各一份），
> 群聊那份不在 `handleGroupMessage` 作用域里 → 编译直接报错。现已收敛成一份。
