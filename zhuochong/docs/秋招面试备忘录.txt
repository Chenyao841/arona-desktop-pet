一、项目一句话 / 30 秒 / 2 分钟
================================================================================

【一句话】
  一个跑在 Windows 桌面上的 AI 桌宠：Electron 做桌面壳与透明置顶窗口，本机 Spring Boot
  提供服务端（对话、记忆、规则、语音、屏幕识别），Live2D 模型负责形象表现，
  可以用语音和我聊天、陪我看直播、点歌、打麻将、给游戏"陪玩点评"。

【30 秒版】
  这是我独立做的一个桌面 AI 桌宠项目，全栈自己写：后端 Java 17 + Spring Boot + MySQL，
  桌面壳是 Electron，前端是原生 HTML/CSS/JS + Live2D Cubism SDK，
  AI 接的是 DeepSeek 大模型，语音用本机跑的 GPT-SoVITS。
  它不是一个"套壳聊天"，而是把大模型接进了桌面环境：能看见屏幕、能操作鼠标、
  有长期记忆和本地规则库、说话有语音和表情动作，还会在自己发呆时自言自语。
  目前 22 张表、规则库 250 条、指令库 63 条，前后端加起来约 1.5 万行自写代码。

【2 分钟版】（结构：是什么 → 架构 → 我的工作 → 亮点 → 结果）
  · 是什么：桌面常驻的 AI 桌宠，透明无边框窗口覆盖在桌面上，可以随时说话、互动、待机自语。
  · 架构：分成三层——
      表现层：Electron 窗口 + Live2D 模型（眼球/呼吸/眨眼/摸头都由参数驱动）
      服务层：本机 Spring Boot（8080），负责对话编排、提示词、记忆、规则匹配、语音合成调用、屏幕识别
      数据层：MySQL 8（22 张表：对话、规则、指令、记忆、事件簿、配置、AI 提示词版本等）
    AI 能力：DeepSeek 对话 + 视觉（截屏理解）、博查联网搜索、本地规则库做确定性兜底
    语音能力：本机 GPT-SoVITS（9880），句级流水线，边说边合成
  · 我的工作：从需求、架构、后端接口、数据库设计、前端交互、Live2D 参数驱动、
    Electron 壳、打包分发，全部自己完成。
  · 亮点：① 语音首句几乎瞬时（响应到达立刻显示文字，TTS 句级并行）；
    ② 桌面级交互难点都啃下来了（透明置顶窗口、区域点击穿透、鼠标跟踪不断线）；
    ③ AI 与规则融合：规则库保证确定性，模型负责表达；④ 屏幕识别 + 自动化（麻将读牌、抽卡）。
  · 结果：单机可跑、可分发（schema.sql + 脱敏种子包），TTS 单句 1~3 秒、缓存命中 0.05~0.28 秒。

三、系统架构与数据流
================================================================================

【进程与端口】
  · Electron 主进程：透明置顶窗口(桌宠) + 托盘 + 全局快捷键 + 本地控制端口 3081
  · Electron 渲染进程：桌宠页面（Live2D + 对话框 + 状态按钮），通过 preload 暴露的
    electronAPI 与主进程通信（contextIsolation 打开，nodeIntegration 关闭）
  · Spring Boot：8080，所有业务接口；静态资源由它托管
  · GPT-SoVITS：9880，本机推理服务
  · MySQL：3306

【一次完整对话的数据流】
  用户输入/点击
    → 前端先过本地指令库（确定性的开关类指令，如"播放音乐""陪我玩"）
    → 否则 POST /talk 交给后端编排：
         · 拼接提示词（人设 system + 功能说明 function + 上下文 + 长期记忆 + 事件簿）
         · 可选注入联网搜索结果 / 屏幕截屏理解结果
         · 调 DeepSeek 得到回复文本
         · 本地规则库匹配（250 条）决定表情/特效/动作 → 返回 boat_text + motion + effect
    → 前端拿到文本后"立即显示 + 立即做表情"，同时异步请求 TTS
    → TTS 句级流水线：第一句合成完就播，播放时后台预合成下一句
    → Live2D 桥接层根据参数驱动眼球/头部/嘴型，播放表情与动作
    → 交互与响应写入事件簿/记忆表，供后续上下文引用

【分层设计要点（面试可讲）】
  1. 表现与智能分离：模型只负责"说什么"，表情/动作/特效由规则层决定 —— 避免 AI 输出格式不稳
  2. 提示词分层且可版本化：ai_prompt 表存 system/function 多版本，可回滚、可 A/B
  3. 规则做兜底、模型做表达：确定性指令走代码/规则库，开放式对话走模型，减少幻觉影响
  4. 记忆分三类：短期上下文（本次对话）、长期偏好（pet_memory）、事件簿（发生过什么）
  5. 语音与文本解耦：文字先到先显示，语音异步跟上（感知延迟≈模型延迟）

四、功能清单与可讲的亮点
================================================================================

【已实现功能】
  · 对话：文字/语音输入，AI 回复 + 语音朗读 + 表情动作，多轮上下文
  · 记忆：长期记忆库、事件簿、"闲置活动"（81 条）待机自语
  · 语音：本地 GPT-SoVITS，可切参考音频/参考文本，多"合成变体"对比音质，语音缓存与一键清空
  · 形象：Live2D 眼球跟随鼠标、眨眼、呼吸、空闲随机视线、摸头、喂牛奶、脸红、眼神动作
  · 桌面交互：透明置顶窗口、区域点击穿透（点桌面不挡）、拖动窗口、锁定穿透、右键托盘
  · 娱乐：网易云点歌/歌单、麻将自动打牌（读牌 + 自动立直/和）、蔚蓝档案自动抽卡
  · 新玩法：陪玩点评（定时截屏 → 一步法视觉点评 → 小音量出声、麻将/抽卡自动暂停）
  · 管理端：桌宠管理页（对话/规则/指令/记忆/表情映射等 CRUD）+ 设置页（11 个模块开关与参数）
  · 工具：区域标注工具（导入本机图片、无损像素坐标、画回图上核对）、操作册、语音合成调试页
  · 分发：建表脚本 + 脱敏种子数据（564 条 INSERT），换机器一键初始化

【亮点（挑两个深讲）】
  亮点 A：语音"首句立即显示 + 句级流水线"
    · 问题：大模型返回 + TTS 合成都需要时间，用户感知延迟长
    · 做法：响应到达即显示文字与表情；TTS 按句切分，第一句合成完即播，
      播放时预合成下一句；服务端提供 /ai/tts/stream 边合成边推
    · 结果：感知延迟≈模型延迟；实测单句合成 1~3 秒、缓存命中 0.05~0.28 秒，冷启动 5.85 秒
  亮点 B：桌面级交互（透明窗口 + 点击穿透 + 视线跟随）
    · 透明置顶窗口既要"能点桌宠"，又要"点桌面不被挡"：自己实现了区域级点击穿透
    · 难点是"恢复"依赖 Electron 的鼠标转发（实测不可靠）→ 主进程兜底 20Hz 读光标位置推给页面
    · 还要和"用户主动锁定""麻将自动化接管"等状态区分开，避免互相顶掉

================================================================================
五、踩坑故事库（重点！建议准备 4~6 个，每个 1.5 分钟）
================================================================================
【讲法模板】现象 → 我怎么定位 → 根因 → 方案 → 学到什么
--------------------------------------------------------------------------------
坑 1｜桌面快捷方式启动报"未找到 DSH"
  现象：点快捷方式启动器直接报错，命令提示符里一堆"不是内部或外部命令"。
  定位：先在真实 cmd 里复现；用十六进制看文件头，发现批处理是 **LF 行尾**。
  根因：cmd.exe 按"CRLF=2 字节"推算文件内偏移，纯 LF 文件会**读错位**，
        把行尾的半个词当命令执行。
  方案：所有 .bat 统一 CRLF + GBK 编码 + 开头 chcp 936，并写进项目坑点手册。
  学到：脚本文件的行尾/编码是"看不见的依赖"，跨工具生成文件时必须校验字节。

坑 2｜换了参考音频，试听和"合成变体"听起来毫无变化
  现象：切换参考音频成功，但试听、变体对比听到的还是旧音色，没法判断音质。
  定位：链路是通的（请求确实用了新音频），于是查缓存 —— 发现缓存键只有 `变体+文本`。
  根因：TTS 缓存按文本 md5 命中旧音频，与音色无关。
  方案：缓存键改为 `变体 + 音色指纹 + 文本`，指纹含"实际参考音频(含语境参考)+参考文本+
        模型路径+语速+采样步数+参考音频文件大小与修改时间"；再加"清空语音缓存"入口。
  学到：缓存键必须覆盖所有影响输出的输入，否则就是"正确性 bug"而不是性能优化。

坑 3｜基础设置窗口"打开看不见、也没有入场动画"，点一下桌面才出现
  现象：桌宠/浏览器在前台时打开设置窗口，什么都不显示；点下桌面才冒出来。
  定位：桌宠窗口是全屏 + always-on-top(screen-saver) 的透明层；设置窗口被压在它下面。
  根因：① 窗口层级问题；② 更关键 —— Windows 会把"被完全遮挡"的窗口报告给 Chromium，
        Chromium 默认**暂停绘制**该窗口，所以内容根本不画。
  方案：设置窗口与桌宠同级置顶 + ready-to-show 时 moveTop/focus +
        `backgroundThrottling:false` + 桌宠失焦时不再抢回置顶。
  学到：桌面端很多"看不见/不刷新"其实是**绘制被节流**，不是逻辑错。

坑 4｜桌宠"僵住"：鼠标移回来没反应，只有快捷键能救
  现象：鼠标移出桌宠区域后再移回来，对话框、按钮、眼部跟踪全无反应。
  定位：用日志确认窗口停在"整窗点击穿透"状态；把穿透状态与光标位置打出来。
  根因：穿透状态下页面靠 Electron 的 mousemove 转发来恢复捕获，而这条转发**不可靠**，
        一旦丢事件就永远回不来。
  方案：主进程兜底 —— 可见且未锁定时 20Hz 读真实光标位置推给页面（顺带给跟踪系统喂坐标）。
  学到：不要把关键状态恢复寄托在"事件一定会到"上，要有主动轮询兜底。

坑 5｜点桌面被"吞"好几次才点到
  现象：点桌宠旁边的桌面图标，要点三四次才生效。
  定位：打印"这次点击算不算点桌面"的判断路径，发现用的是包含**模型画布外框**的热区。
  根因：模型外框比可见身体大一圈 → 大片桌面被误判成桌宠区域 →
        "点桌面放开捕获 → 轮询又抢回 → 下一次又被吞"的循环。
  方案：判断改用"只看 UI 热区"，另加 1.2 秒宽限期，宽限期内用**更紧的模型命中**决定是否抢回。
  学到：命中区"大一点更好点"和"太大会误判"是要用两套阈值分开处理的。

坑 6｜视线跟随被穿透"冻住"，回场时猛地甩过去
  现象：鼠标出桌宠区后视线不动了，一回来眼睛"啪"地甩过去。
  定位：跟踪目标是靠最近一次 mousemove 坐标算的，穿透后收不到事件 → 坐标冻结。
  根因：恢复用指数硬追；且"断档判定"写在了更新时间戳之后，永远不触发。
  方案：断档判定必须在更新时间戳**之前**；恢复/归位统一用与"空闲随机视线"相同的
        easeInOut 缓动（0.32~0.94 秒，距离越远越久）。
  学到：动画类问题先分清"目标值错"还是"过渡曲线错"。

坑 7｜Live2D 眼球"瞪"而不是跟随
  现象：按直觉写 ±10 的偏移量，眼球直接顶到极限，看起来像瞪人。
  定位：打印模型参数实际量程，发现 ParamEyeBallX ∈ [-1,1]、ParamEyeBallY ∈ [-3,0.8] **非对称**。
  方案：按量程归一化换算，并把"零点"从模型默认值读取；上/下量程分别映射。
  学到：接第三方渲染引擎第一步是"量参数"，别凭直觉写系数。

坑 8｜运行期写入 static 目录的图片，浏览器 404
  现象：后端把图片写进 src/main/resources/static/xxx，页面访问却取不到。
  根因：classpath 下的 static 是**编译时拷进 target/classes** 的，运行期写源目录不会生效。
  方案：在 WebConfig 里给该目录配**文件系统直出**的 ResourceHandler（file: 绝对路径）
        ＋ 拦截器白名单，导入即用、免 rebuild。
  学到：分清"静态资源"与"运行期产出文件"两类路径，后者的可访问性要显式配置。

坑 9｜换了新图标，桌面快捷方式还是旧图
  现象：ICO 生成成功、快捷方式也指过去了，桌面按 F5 仍是旧图标。
  根因：Explorer 图标缓存按"图标文件路径"做键，同路径换内容继续用缓存；
        另外 Windows 只对 256 这一档官方支持 PNG 内嵌，小尺寸要用 DIB 位图。
  方案：ICO 换新路径（统一放 图标/ico/）+ ie4uinit 重建缓存 + 小尺寸用 DIB。
  学到：系统级缓存要主动失效，别假设"文件变了界面就会变"。

坑 10｜命令行窗口启动时"闪一下"
  现象：双击快捷方式会闪一个 cmd 窗口；想让它完全不出现。
  定位：Electron 的 spawn 会给子进程加 DETACHED_PROCESS（没有控制台，日志窗口不显示），
        PowerShell -WindowStyle Hidden 也会先建控制台再隐藏（偶尔闪帧）。
  方案：用 VBS 的 WshShell.Run(cmd, 0, False) 真正无窗口启动，输出重定向到日志文件；
        再配托盘"打开日志目录"。
  学到：Windows 上"隐藏窗口启动"有明确的最佳实践，别用间接方案硬凑。

坑 11｜首次跑项目必须先建表 + 填默认数据
  现象：换机器/清库后项目跑不起来（表不存在）。
  方案：Mapper 里带 createTableIfAbsent，启动时自举建表并检查种子数据；
        另导出 db/schema.sql + db/seed.sql（564 条 INSERT，已脱敏：Key/Cookie/本机路径/房间号全部清空）。
  学到：种子数据脱敏要按行处理，正则"从 Key 到分号"会把真实凭据一起带出去（踩过一次）。

坑 12｜排查效率本身也是能力（工具链小坑合集）
  · PowerShell 里 `@('a','b' + $x)` 会因为**逗号优先级高于加号**被拆成三个元素，
    生成出来的批处理直接是坏文件 → 定位到后改成"每行先赋值再入数组"。
  · Windows PowerShell 5.1 按 GBK 读 .ps1，无 BOM 的 UTF-8 脚本中文注释会吃掉引号 → 一律带 BOM。
  · Electron 主进程日志写中文在 GBK 控制台必然乱码 → 主进程日志统一 ASCII，中文只放页面控制台。
  学到：调试环境本身也会骗人，遇到"不可能的错误"先怀疑工具链。

六、分岗位追问预判与答法
================================================================================

【A. AI 应用开发工程师】
  Q1 提示词怎么组织？怎么避免模型"跑偏"？
    → 分三层：system 人设 + function 能力说明 + 本轮上下文/记忆；
      输出侧不信任模型格式：表情/动作/特效由本地规则库（250 条）决定，模型只说人话；
      关键指令（开机、点歌、停止麻将）走代码/指令库，不用模型判断。
  Q2 上下文和记忆怎么管？token 怎么控？
    → 短期：本次对话按轮次裁剪；长期：pet_memory（偏好/称呼）+ event_book（发生过的事件）；
      组装时按相关性取，超出预算就丢最旧/最低相关的；提示词版本化，可回滚与对比。
  Q3 视觉能力怎么接的？
    → 截屏 → 缩放到 800px 宽（更宽模型会返回空）→ 走视觉模型；输出只要一行 JSON；
      陪玩点评用"一步法"（不做多轮 agent），并做 64×40 灰度变化检测避免无变化重复点评。
  Q4 成本和延迟怎么优化？
    → 本地 TTS 不花钱、不上云；对话用轻量模型 + 输出长度限制；
      首句立即显示、TTS 句级并行、缓存（键含音色指纹）；截屏按需触发而不是常开。
  Q5 怎么评估效果？
    → 人工 A/B（试听变体对比）、规则命中率日志、事件簿回看；承认缺少自动化评测，列了改进计划。

【B. 桌面端 / 客户端开发工程师】
  Q1 Electron 进程模型与安全？
    → 主进程管窗口/托盘/全局快捷键/本地控制端口；渲染进程只跑页面；
      contextIsolation 开、nodeIntegration 关，能力通过 preload 的 contextBridge 白名单暴露。
  Q2 透明置顶窗口的坑？
    → 层级要与其它置顶窗口同级；透明+无边框时"看不见"常是**绘制被遮挡节流**（backgroundThrottling）；
      点击穿透状态要和"用户主动锁定""自动化接管"区分，避免互相顶掉。
  Q3 单实例怎么做的？
    → requestSingleInstanceLock，抢不到锁的进程 app.quit() 并 return，
      提醒由已运行实例的 second-instance 事件弹出（顺带解决重复双击）。
  Q4 动画/性能怎么保证？
    → 位移动画用 setPosition 只改坐标（透明窗口重绘更稳）；时间驱动的缓动而非帧计数；
      Live2D 参数平滑用统一缓动函数；不在高频路径做 DOM 查询。
  Q5 打包分发？
    → 目前是绿色包思路：Electron 壳 + 后端 jar + 建表/种子脚本；
      模型与素材不随包分发（体积大、且涉及第三方版权），README 写明"仅供学习"。

【C. 全栈开发工程师】
  Q1 接口怎么设计？
    → 统一 Result 信封（code/message/data）；按模块分 Controller；
      白名单集中在 WebConfig（新接口必须显式放行，否则被拦截器 401）；
      写操作带幂等/重复校验（指令库重复会标红）。
  Q2 鉴权怎么做的？
    → JWT（id/username/identity）；拦截器拦截非白名单；员工身份全局只读；
      管理员页与设置页共用同一登录态。
  Q3 数据库怎么设计？
    → 22 张表按领域分：对话/选项、规则库、指令库、闲置活动、记忆与事件簿、配置与提示词、
      表情与部位映射、TTS 参考、评论语境等；Json 字段能扩就不用加表；
      自举建表 + 种子数据保证"换机可跑"。
  Q4 前后端怎么协作与联调？
    → 同源（后端托管静态页面）省掉 CORS；接口用 axios；日志前缀区分模块（[AI]/[TTS]/[麻将]…）；
      统一"页面 Ctrl+F5、Java 重启后端、Electron 改动重开"的联调节奏。
  Q5 部署与分发？
    → 本机桌面形态：后端 + Electron + 本地 TTS；分发走"建表脚本 + 脱敏种子 + 依赖提示"；
      QQ 机器人上云方案已写文档（cloud profile、容器化清单）。

【D. 通用/行为面】
  Q 项目里最难的问题？
    → 引用坑 3/4/5/6 一组"桌面窗口与鼠标交互"的问题：现象都在表现层，
      根因却分别在窗口层级、Chromium 绘制节流、事件转发可靠性、命中区阈值。
    → 我的方法论：先复现 → 用日志/最小实验把范围夹到一层 → 再改；
      改完一定回写"坑点手册"，避免同一个坑踩两次。
  Q 你一个人做，怎么保证质量？
    → 自测清单 + 手工回归（每改一个功能列验证步骤）；
      关键数据有日志与调试页（语音调试、区域标注、参数巡览）；
      诚实承认：没有自动化测试与 CI，这是下一步要补的。
  Q 如果重做一遍会怎么改？
    → ① 配置外置（DB/路径走环境变量与 profile，去掉硬编码）；
      ② 抽象"表现规则"为可热更新的配置，减少改代码；
      ③ 加接口层单测 + 关键流程的冒烟脚本；
      ④ 桌面交互状态机化（穿透/锁定/自动化三种状态做成显式状态机）。
  Q 为什么选原生 JS 而不用框架？
    → 页面 UI 规模不大但和渲染（Live2D/Canvas）耦合深，原生更可控、启动更快；
      代价是状态管理靠约定，已在往"状态机化"收敛。
